# Phase 38 — Database Migration Readiness

## Changes
- Added `scripts/check-migration-chain.sh` and `npm run db:migration-check` to verify the PostgreSQL migration lock, required baseline SQL, ordered migration directory names and non-empty SQL files.
- The VPS pre-deployment guard now runs the migration-chain check before allowing deployment.
- Hardened `scripts/create-baseline-migration.sh`: it writes Prisma-generated SQL to a temporary file first and only installs the migration after generation succeeds. A failed Prisma invocation no longer leaves an empty baseline directory that prevents retry.
- The baseline SQL remains generated by the project's pinned Prisma CLI from `prisma/schema.baseline.prisma`; it is deliberately not hand-authored or fabricated.

## Current migration state
The cumulative source has eight delta migrations after the preserved pre-Google baseline schema. The actual initial migration SQL is not present in this source bundle. This is an explicit deployment blocker until it is generated and reviewed.

## Checks performed in this phase
- Source-contract tests cover the retry-safe generator and pre-deployment guard.
- Shell syntax checks cover the new checker and existing scripts.
- The migration checker is expected to fail on this source snapshot because the initial baseline SQL has not yet been generated. That failure is intentional and prevents an unsafe fresh-database deployment.

## Commands for the local development machine
After installing dependencies and configuring a disposable/local PostgreSQL database:
1. `npm install` (creates the lockfile for this exact dependency resolution; review and keep `package-lock.json`).
2. `npm run db:baseline:generate`.
3. Review `prisma/migrations/20261122000000_initial/migration.sql`.
4. `npm run db:migration-check`.
5. `npx prisma validate`.
6. `npx prisma generate`.
7. Test `npx prisma migrate deploy` against a fresh disposable database before using production data.

For an existing database, do not run the fresh migration chain blindly. Compare the live schema to the baseline, take and verify a backup, and use Prisma's baseline resolve workflow only after confirming schema equivalence.
